# vaultwarden-k3s

Deploy [Vaultwarden](https://github.com/dani-garcia/vaultwarden) on a [k3s](https://k3s.io/) homelab with almost no Kubernetes knowledge.

Vaultwarden is a lightweight, self-hosted [Bitwarden](https://bitwarden.com/)-compatible password manager server.

This repo follows Vaultwarden’s current guidance:

- Image: `vaultwarden/server:latest`
- Data volume: `/data`
- Set **`DOMAIN`** to the URL people will use ([required for attachments / WebAuthn / links](https://github.com/dani-garcia/vaultwarden/wiki))
- Keep **`SIGNUPS_ALLOWED=true` only long enough** to create your first account, then turn it off ([Hardening Guide](https://github.com/dani-garcia/vaultwarden/wiki/Hardening-Guide))
- Store **`ADMIN_TOKEN`** in a Kubernetes Secret (generated by `install.sh`) — see [Enabling admin page](https://github.com/dani-garcia/vaultwarden/wiki/Enabling-admin-page)

## What you need

1. A working **k3s** cluster (`kubectl` talks to it)
2. **Longhorn** storage (or change `storageClassName` in `deploy.yaml`)
3. `openssl` (used by `install.sh` to generate the admin token)

## One-time: install Longhorn

```bash
helm repo add longhorn https://charts.longhorn.io
helm repo update
helm install longhorn longhorn/longhorn \
  --namespace longhorn-system --create-namespace

kubectl -n longhorn-system get pod
```

Longhorn creates the volume automatically from the PVC. You do **not** need to create a volume by hand in the Longhorn UI.

## Install Vaultwarden

```bash
git clone https://github.com/johnycsf/vaultwarden-k3s.git
cd vaultwarden-k3s
chmod +x install.sh

# Optional: set the public URL people will use (https recommended behind a reverse proxy)
DOMAIN=http://192.168.1.50:8081 ./install.sh
```

If you omit `DOMAIN`, the script uses `http://<first-node-internal-ip>:8081`.

The script will:

1. Apply `deploy.yaml` (namespace, PVC, deployment, service)
2. Generate a random `ADMIN_TOKEN` and write it into a Secret
3. Save the token locally to `.admin-token` (gitignored)
4. Wait until the pod is ready

## Open Vaultwarden

```bash
kubectl -n vaultwarden get svc vaultwarden
```

- Web vault: `http://EXTERNAL-IP:8081/` (or your `DOMAIN`)
- Admin page: `http://EXTERNAL-IP:8081/admin` — password is the value in `.admin-token`

### Right after first login (important)

1. Create your account while signups are still allowed.
2. Disable public registration (Vaultwarden hardening recommendation):

```bash
kubectl -n vaultwarden set env deployment/vaultwarden SIGNUPS_ALLOWED=false
kubectl -n vaultwarden rollout status deployment/vaultwarden
```

## Harden further (recommended)

- Put Vaultwarden behind HTTPS with a reverse proxy (Caddy / Traefik / nginx). Then reinstall or patch the Secret so `DOMAIN` is `https://vault.example.com`.
- Prefer an Argon2id-hashed admin token for long-term use:

  ```bash
  docker run --rm -it vaultwarden/server /vaultwarden hash
  ```

  Put the resulting `$argon2id$...` string into the Secret’s `admin-token` key.
- Do not expose port `8081` to the public internet without TLS and signup lockdown.

## Customize

| Setting | Where | Notes |
|--------|--------|--------|
| Public URL | Secret key `domain` / `DOMAIN=` on install | Must match how users open the app |
| Signups | `SIGNUPS_ALLOWED` | `true` initially, then `false` |
| Disk size | PVC `storage` | Default `10Gi` |
| Service port | Service `port` | Default `8081` → container `80` |

## Update

```bash
kubectl -n vaultwarden set image deployment/vaultwarden \
  vaultwarden=vaultwarden/server:latest
kubectl -n vaultwarden rollout status deployment/vaultwarden
```

## Uninstall

```bash
kubectl delete -f deploy.yaml
rm -f .admin-token
```

This deletes the PVC and your vault database.

## Notes for beginners

- One replica only — the SQLite database in `/data` is not multi-writer.
- Older versions of this repo told you to create Longhorn volumes manually and referenced a missing `vaultwarden-svc.yaml`. That is no longer needed: everything is in `deploy.yaml`, and the PVC uses the `longhorn` StorageClass for dynamic provisioning.
